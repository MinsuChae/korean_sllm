## 1. 검토 배경

노트북 6번 셀은 `train.jsonl` 앞 2,000줄로 토큰 통계를 내고 "시퀀스 길이 2048이면 샘플당 여유 충분(최대 1,860 tokens)"이라고 결론지었다.
그러나 [merge_jsonl.py](../merge_jsonl.py)는 **파일명 정렬 순서로 이어 붙이고 셔플하지 않으므로** 앞 2,000줄은 전부 `koalpaca-v1.1a_train.jsonl` 이다.
KoAlpaca 는 6개 소스 중 가장 짧은 축(평균 234 tokens)에 속하므로, 이 통계로 전체 데이터의 시퀀스 길이를 정하면 긴 소스(KULLM-v2)를 과소평가하게 된다.

→ 본 검토에서는 `train/*.jsonl` 301,669 샘플 전체를 실제 학습 인코딩(`data.encode_sample`, 챗 템플릿 포함)으로 토크나이즈해 재집계했다.

### 2-3. 챗 관점 — 질문과 답변을 나눠서 보면

| 구간 | 평균 | p50 | p90 | p99 | 최대 |
|---|---:|---:|---:|---:|---:|
| 질문(프롬프트, 템플릿 포함) | 68 | 26 | 113 | 1,077 | 10,992 |
| 답변(+`<end_of_turn><eos>`) | 231 | 157 | 466 | 989 | 4,201 |

- 챗 환경의 **사용자 질문은 대부분 100 tokens 안팎**이다. 질문이 1,000 tokens 를 넘는 경우는 1% 미만이며, 이는 "다음 글을 요약하라"류의 긴 입력문 태스크다.
- **답변은 p90 ≈ 470, p99 ≈ 990 tokens.** 추론 시 `max_new_tokens=512` 면 답변 분포의 약 92%, `1024` 면 99% 이상을 잘림 없이 생성할 수 있다. 현재 `generate()` 기본값 256 은 데모용으로는 되지만 답변 중앙값(157)만 겨우 넘기는 수준이라 실사용 시 512 이상을 권고한다.

| 길이 구간 | 샘플 비중 | 토큰 비중 |

| 513–768 | 7.4% | 15.2% |

샘플 수로는 87%가 512 이하지만, **토큰 수로는 512 초과 샘플이 37%를 차지**한다. 즉 학습 신호(토큰) 기준으로는 긴 샘플의 비중이 결코 작지 않다.

## 3. seq_len 후보 비교

현재 파이프라인은 샘플을 그대로 이어 붙여 `seq_len` 단위 비중첩 윈도우로 자르는 **단순 패킹**이다([data.py](../data.py) `PackedDataset`). 따라서 seq_len 은 "잘라내는 한계"가 아니라 **한 윈도우에 몇 샘플이 들어가고, 얼마나 많은 샘플이 윈도우 경계에서 두 동강 나는가**를 결정한다.

| seq_len | 윈도우 수 | 윈도우당 평균 샘플 | 경계에서 잘리는 샘플 (추정) | L 초과 샘플 | 1 epoch 스텝 수* | 20k 스텝 = 에폭 |
|---:|---:|---:|---:|---:|---:|---:|
| 512 | 176,376 | 1.7 | ≈ 58% | 12.7% | 5,511 | 3.6 |
| 1024 | 88,188 | 3.4 | ≈ 29% | 2.6% | 2,756 | 7.3 |
| **2048** | 44,094 | 6.8 | ≈ 15% | 0.4% | 1,378 | 14.5 |

\* `batch 8 × grad_accum 4` 기준. "경계에서 잘리는 샘플" ≈ 윈도우 수 / 샘플 수 (샘플 하나가 여러 윈도우에 걸치는 경우 포함).

- **512**: 절반 이상의 샘플이 질문과 답변 사이 어딘가에서 잘린다. 잘린 뒷부분은 질문 없이 답변만 보는 셈이 되어 챗 형식 학습에 가장 불리하다. 의학 QA(평균 434)는 20%가 통째로 512 를 넘는다.
- **1024**: 잘림 29%, KULLM-v2 의 6%가 초과. 메모리가 부족할 때의 차선.
- **2048**: 잘림 15%, 초과 0.4%. 모델의 `max_seq_len`·RoPE 캐시와 일치하고, 추론 시 컨텍스트(질문 p99 1,077 + 답변 p99 989 ≈ 2,066)도 거의 전부 수용한다. sliding window 512 는 로컬 층에서 답변 p90(466)을 한 창 안에 넣는 크기라 2048 과 조합이 자연스럽다.

## 4. 결론 및 권고

### 4-1. 결정: 학습 seq_len = 2048 유지

노트북의 결론(2048)은 **유지**하되, 근거는 "최대 1,860 이라 여유 충분"이 아니라 아래로 바꾼다.

> 전체 301,669 샘플의 99.58%가 2048 이내이고(p99 1,483), 단순 패킹에서 윈도우 경계 잘림이 15% 수준으로 억제되며, 추론 컨텍스트(질문 p99 + 답변 p99 ≈ 2,066)와 모델 `max_seq_len` 에 부합한다.

### 4-2. 함께 반영할 사항 (권고 순)

1. **2048 초과 샘플 필터링 — 반영 완료**
   1,272개(0.42%, 토큰 3.9%)가 seq_len 을 넘는다. 이들은 어차피 추론 시 `max_seq_len=2048` 로 처리할 수 없는 길이이고, 패킹 시 2~6개 윈도우에 걸쳐 질문 없는 답변 조각을 만든다. [data.py](../data.py) `build_cache(max_sample_len=...)` 에서 `len(ids) > max_sample_len` 인 샘플을 통째로 건너뛰도록 했고(전부 KULLM-v2 라 소스 균형에 영향 없음), [train.py](../train.py) 는 `--max-sample-len` 미지정 시 seq_len 을 그대로 넘긴다(`0` 이면 해제). 필터 값이 캐시 파일명(`train_tokens_max2048.npy`)에 들어가므로 값이 바뀌면 캐시가 자동으로 재생성된다. 답변만 잘라 남기는 방식은 `<eos>` 없는 답변을 학습시키므로 채택하지 않았다.
   실측: train 300,397줄 / 86,752,276 tokens, val 33,384줄 / 9,660,739 tokens 캐시 생성(각각 1,272줄·135줄 제외). 필터 후 1 epoch ≈ 86.75M / 65,536 ≈ **1,324 스텝**이므로 Colab 의 5,500 스텝은 약 4.2 epoch 이다.
   주의: `--preset tiny`(seq 128) smoke test 에서는 기본 필터가 128 이 되어 샘플의 75% 가 빠진다 — 동작 확인 용도라 무방하지만, 전체 데이터로 돌리려면 `--max-sample-len 0` 을 준다.
2. **max_steps 재산정 — Colab 노트북 반영 완료**
   seq 2048 기준 1 epoch ≈ 1,378 스텝인데 `train.py` 기본 `--max-steps 20000` 은 **14.5 epoch** 에 해당한다. 90M 토큰(손실 대상 69.5M) 규모의 SFT 데이터를 14회 반복하면 과적합 가능성이 높다. [colab_train.ipynb](../colab_train.ipynb) 학습 셀을 `--seq-len 2048 --max-steps 5500(≈4 epoch) --warmup-steps 300 --eval-every 250 --save-every 500` 으로 바꾸고 생성 데모 `max_new_tokens` 를 512 로 올렸다. `train.py` 의 기본값 20,000 자체는 그대로 두었으므로 README 의 인자 없는 실행 예시는 여전히 14.5 epoch 를 돈다 — 기본값도 낮출지는 별도 결정. seq_len 을 바꾸면 스텝당 토큰이 달라지므로 max_steps 도 함께 조정해야 한다.
3. **노트북 6번 셀 표본 수정 — 반영 완료**
   앞 2,000줄 대신 파일 전체에서 등간격 표본을 뽑도록 수정해, 노트북만 돌려도 전체 분포에 가까운 수치가 나오게 했다.
4. **패킹 시 샘플 간 어텐션 차단 — 참고 (이번에는 미반영)**
   현재 어텐션 마스크는 causal + sliding window 만 적용하고([model.py](../model.py) `local = causal & (q_pos - k_pos < sliding_window)`) 샘플 경계를 구분하지 않는다. 한 윈도우 안의 뒤쪽 샘플이 앞쪽 샘플(대부분 같은 소스)을 볼 수 있다. 사전학습에서 흔히 허용하는 단순화이고 160M 규모에서 영향은 제한적이라 이번 결정에는 포함하지 않되, 품질 개선 여지가 필요해지면 문서 ID 기반 블록 대각 마스크(또는 best-fit 패킹)를 검토한다.
5. **추론 생성 길이 — 참고**
   답변 p90 466 / p99 989 tokens. 실사용 `max_new_tokens` 는 512 이상(가능하면 1024)으로 두고, 현재 `generate()` 기본값 256 은 데모 전용으로 본다.
